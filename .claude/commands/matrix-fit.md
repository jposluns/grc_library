Run the `matrix-fit` procedure defined at [`.claude/skills/corpus-management/procedures/matrix-fit.md`](../skills/corpus-management/procedures/matrix-fit.md). Slash-command entry point is `/matrix-fit`; the underlying procedure name remains `matrix-fit`. This is the cadenced semantic-fit audit of the compliance matrix and per-document framework-alignment tables, catching the gate-blind "valid code, wrong control" class (a control identifier that exists in its catalogue, so existence gates 48/49/54/58/61 pass it, but is the wrong control for the row's document). Run it after each batch that adds or edits mapping rows, once at completion of a mapping surface, and ad-hoc. Execute the audit per the six-step process the procedure encodes:

1. **Establish scope and confirm the reference base**: name the scope (the batch's rows, the whole surface for the completion cadence, or a flagged set). Confirm `.claude/skills/corpus-management/tools/run_all_audits.sh` exits 0 first. Confirm the reference base is available: the in-repo validator modules [`ccm_aicm_reference.py`](../skills/corpus-management/tools/ccm_aicm_reference.py), [`nist_csf_reference.py`](../skills/corpus-management/tools/nist_csf_reference.py), [`cobit_iso31000_reference.py`](../skills/corpus-management/tools/cobit_iso31000_reference.py), and [`iso27001_reference.py`](../skills/corpus-management/tools/iso27001_reference.py) (gate-validated codes and titles) plus the project's held source-text extracts. Titles are read from these, never from memory.
2. **Build the worklist**: the batch's rows, the flagged set, or EVERY row of the surface for the completion cadence; add anything the maintainer or a prior sweep note flagged. An optional deeper review may supplement the public gates by narrowing the worklist; treat any such output as input-narrowing, never a defect list.
3. **Judge each worklisted row**: read the cited control's TITLE from the reference base for every code on the row, compare it against the row's document subject, and decide fit (`fits` / `mismatch` / `loose-supporting` / `title-not-held`) with the source title quoted as evidence. Every fit judgement quotes the code, its source title, the row `path:line`, AND the held source title's own reference-base `path:line` read via an executed reference-base index read in THIS run; the one exception is a `title-not-held` verdict, which carries that executed index read as its absence evidence instead. A same-family wrong-sibling is a `mismatch`; family membership never establishes fit. The indicative-citation convention governs literal presence only: a stranded code is not a defect on that ground alone, but it is still judged for fit.
4. **Apply-time-verify**: re-read each candidate `mismatch` and `loose-supporting` source title in the reference base before confirming; refute false positives rather than routing them. For each confirmed mismatch, identify the proposed right code with both titles quoted; re-read the paired description cell for stale echoes. Verify a candidate `title-not-held` with your OWN executed reference-base index read.
5. **Triage and route**: fix confirmed in-scope mismatches in-window (correct the code, bump Version and Date, write the change record); surface out-of-scope mismatches with named options. A confirmed `loose-supporting` is retained as indicative and recorded, never "corrected". A confirmed `title-not-held` is routed acquisition-first: attempt the ingest, queue only a failed or constrained attempt, and re-judge after a successful ingest.
6. **Record and present**: surface confirmed findings inline (a `mismatch`: row `path:line`, wrong code and source title, proposed right code and source title, each title's held-source reference-base `path:line`, fix vs routed; a retained `loose-supporting`: row `path:line`, code, title, held-source `path:line`, retention rationale; a `title-not-held`: the code, the row `path:line`, the executed index read absence evidence, and its acquisition attempt or routing). Record the run in the project's own working records; a run with none of the three still gets a one-line record.

Reject any fit judgement that lacks an explicit row `path:line`, a quoted source control title, AND the title's held-source reference-base `path:line` (for a `title-not-held` verdict, the required evidence is instead its executed reference-base index read establishing the absence). A judgement without quoted evidence is a hypothesis, not a finding.

`matrix-fit` does NOT replace existence gates 48/49/54/58/61; it is the semantic layer on top of them. Passing the gates says nothing about fit.

Report back: the scope and mechanical baseline, the worklist, every verdict (per `mismatch`: row `path:line`, wrong code plus source title, proposed right code plus source title, each title's held-source reference-base `path:line`; per retained `loose-supporting`: row `path:line`, code, source title, held-source `path:line`, retention rationale; per `title-not-held`: the code, the row `path:line`, the executed index read absence evidence, and its acquisition attempt or routing), the apply-time verification outcomes (confirmed vs refuted), the fixes applied and the items routed, and where the run was recorded.
