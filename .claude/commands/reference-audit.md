Run the `reference-audit` procedure defined at [`.claude/skills/corpus-management/procedures/reference-audit.md`](../skills/corpus-management/procedures/reference-audit.md). Slash-command entry point is `/reference-audit`; the underlying procedure name remains `reference-audit`. This is the cadenced reference-breadth audit between the corpus and the held reference base, in both directions, catching the gate-blind "held but unused" class (an authoritative source sits in the reference base while corpus documents its content would materially improve never engage it) and the reverse (a corpus document is touched while newly ingested or updated reference material that bears on it goes unnoticed). Trust tiers are load-bearing: standards, frameworks, legislation, and programs are authoritative (citation-grade improvements); templates are template-tier (content improvements, never normative citations); books are recommendation-tier only, never authoritative; publications are excluded until screened. Execute the audit per the seven-step process the procedure encodes:

1. **Establish scope, mode, and the reference baseline**: name the mode (FULL, per-touch with the touched document list, or new-ingest with the reference delta) and confirm `.claude/skills/corpus-management/tools/run_all_audits.sh` exits 0 first. Confirm the reference base is available via its indexes; the per-source currency rule applies to any source a finding will rest on.
2. **Build the candidate worklist**: pair source items with project documents by topic for the mode's scope. An optional deeper review may supplement the public gates by classifying item usage and ranking candidates; treat any such output as a recall-oriented worklist, never a defect list. An empty per-touch candidate set ends the run with a one-line record; no review on an empty set.
3. **Judge each candidate pairing**: read the corpus document in full, locate the held item's text via the reference-base indexes and read the relevant sections, and return one of `adopt-citation` / `adopt-content` / `recommend` / `no-fit` with the CONCRETE improvement named and the source passage or structure quoted or pinpointed as evidence. Judge against the held text and the live document, never a title, topic labels, or memory; respect the tier ceiling (a book can never yield `adopt-citation`; a template yields `adopt-content`). In FULL mode, give every uncited and thinly-cited authoritative item an explicit disposition.
4. **Apply-time-verify**: re-read each `adopt-citation`, `adopt-content`, and `recommend` verdict's evidence before confirming; refute false positives (already engaged under different phrasing, passage does not support the verdict, sibling document covers it) rather than routing them. Draft each confirmed improvement per its verdict and tier, naming the corroborating trusted source for any `recommend`.
5. **Triage and route**: fix small confirmed in-scope improvements in-window (apply, bump Version and Date, write the change record); route substantive improvements to the backlog with evidence attached and named options; record FULL-mode out-of-scope dispositions durably; record refutations; cross-reference duplicates.
6. **Update the per-document state**: record, in the project's own working records, the reference-base revision each adjudicated document was audited against, and commit the refresh with the change's QA batch. A document with no state record is treated as never audited and gets the full candidate set on its next touch.
7. **Record and present**: surface confirmed findings inline (document path, held item and tier, verdict, concrete improvement, action taken or option surfaced). Record the run; a zero-finding or empty-candidate run still gets a one-line record.

Reject any verdict that lacks the concrete improvement and pinpointed evidence (source passage or structure plus document section), and any verdict that breaches its tier ceiling. A verdict without named evidence is a hypothesis, not a finding.

`reference-audit` does NOT replace the citation gates or the sibling semantic audits; it is the breadth layer beside them. A confirmed `adopt-citation` finding lands as a normal corpus change that passes all of those gates, and any new normative value it introduces hands off to `/claim-fit`'s cadence.

Report back: the mode and scope with the mechanical baseline, the worklist (classification and candidate counts), the verdicts (per pairing: document, held item and tier, verdict, evidence), the apply-time verification outcomes, the improvements applied and the items routed with options, the state refresh, and where the run was recorded.
