Run the `validation-sweep-pr-scoped` procedure defined at [`.claude/skills/corpus-management/procedures/validation-sweep-pr-scoped.md`](../skills/corpus-management/procedures/validation-sweep-pr-scoped.md). Slash-command entry point is `/validate-pr`; the underlying procedure name remains `validation-sweep-pr-scoped`. Execute the change-scoped pre-merge sweep per the five-step process the procedure encodes:

1. **Identify the change set being finalized**: capture the base revision (`git merge-base <base-branch> HEAD`), the diff against it (`git diff <base>...HEAD`, branch synced to the base branch), and the list of touched files (`git diff --name-only <base>...HEAD`).
2. **Establish mechanical baseline**: sync the branch to the current base branch, then run `.claude/skills/corpus-management/tools/run_all_audits.sh` standalone against it. If any gate fails, fix the underlying defect first (in this change, or a separate fix when it is pre-existing and out of scope), then return to step 1.
3. **Review the change's diff in depth**: the reviewer receives the diff, the touched-file list, the full state of each touched file, and the pre-flight scanner output filtered to the touched files (`python3 .claude/skills/corpus-management/tools/sweep-preflight-scanner.py`, filtered; proceed unhinted when nothing is relevant). Check the eight failure-mode classes from the corpus-wide procedure, scoped to the touched files: stale prose references, mis-attributed citations, multi-surface incompleteness, inferred-as-verified state assertions, version-bump omission, generated-artefact lag, stale docstrings in touched Python files, cross-document term drift. Findings are SARIF-lite blocks; every finding must quote a specific `path:line`. **Pre-tool verification preamble (AI-assisted review)**: an AI-assisted reviewer states in one line, before each tool call, (a) the hypothesis the call tests, (b) the observation that would falsify it, and (c) one prior result that does not already answer the question, and verifies the previous call's actual result before relying on it; an undefined falsifier means skip the call as corroboration-only. A review transcript that chains calls without these per-call statements is rejected and the review is redone. Shared-tree safety: inspect history READ-ONLY (`git show`, `git diff`, `git log`); never run `git checkout` / `switch` / `reset` or anything that moves the working tree's branch or HEAD.
4. **Targeted cross-reference check**: for each touched file, find the OTHER files that cite it (`grep -rln "<basename>" --include="*.md"`) and do a shallow check per citer: does the citation still resolve, has the touched file's header text broken the citer's quoted text, has any cross-reference gone stale?
5. **Triage and record**: in-window findings (introduced by this change) are fixed in THIS change before finalizing; out-of-window findings (pre-existing, exposed) are surfaced to the maintainer with named options. Record the run in the project's own working records (change identifier, date, findings or the zero-finding result, dispositions, cross-reference result). Before recording a fixed-in-window claim, verify the edit against the actual diff; a claim whose edit is absent is recorded as routed, never as fixed.

Run this sweep on every change set before it merges, however small; record any maintainer-granted exception with its rationale. Do not substitute an abbreviated check, a spot-check, or a memory-only review for the formal review the procedure encodes. A zero-finding run is itself recorded: the record is the proof the check ran.

Reject any review finding that lacks an explicit `path:line` quote; a finding without quoted evidence is a hypothesis, not a finding.

**Present findings prominently**: when findings exist, enumerate them inline (ruleId, severity, `path:line`, one-line evidence quote, impact, recommendation, in-window vs out-of-window). A zero-finding run gets a one-line acknowledgement.

Report at the end: the audit baseline result, the review findings, the cross-reference check results, the triage decisions, and where the run was recorded.
