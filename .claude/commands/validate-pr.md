Invoke the `validation-sweep-pr-scoped` skill defined in this project's pack at [`dev-security/claude-rules/skills/validation-sweep-pr-scoped/SKILL.md`](../../dev-security/claude-rules/skills/validation-sweep-pr-scoped/SKILL.md). Slash-command entry point is `/validate-pr`; the underlying skill name remains `validation-sweep-pr-scoped` (the descriptive name documents the workflow's purpose, the slash command is the ergonomic verb). Execute the PR-scoped pre-merge finalizing regression sweep per the five-step process the skill encodes:

1. **Identify the PR being finalized**: capture its PR number (from the open PR, e.g. `gh pr view` or `mcp__github__pull_request_read`), the PR's diff against its base (`git diff <base>...HEAD` on the branch, synced to current `main`), and the list of touched files (`git diff --name-only <base>...HEAD`).

2. **Establish mechanical baseline (pre-merge, branch synced to `main`)**: sync the PR branch to current `main`, then run `tools/run_all_audits.sh` standalone against it. CI ran this on the branch; this confirms the gates are clean before the PR is finalized. If any gate fails, fix the underlying defect first (in this PR, or a hot-fix PR if it is pre-existing and out of scope), then return to step 1.

3. **Dispatch Subagent A scoped to the PR's diff**: Subagent A receives the PR diff, the list of touched files, the full state of each touched file on the branch, and a pre-flight scanner output filtered to the touched files (run `python3 tools/sweep-preflight-scanner.py` and filter to the touched-file set). Subagent A looks for the same eight failure-mode classes from the corpus-wide `validation-sweep` SKILL, scoped to the touched files: (a) stale prose references, (b) mis-attributed citations, (c) multi-surface incompleteness, (d) inferred-as-verified state assertions, (e) per-document version-bump omission, (f) generated-artefact lag, (g) stale docstrings in any touched Python file, (h) cross-document term drift. **Pre-tool verification preamble**: the subagent brief instructs the subagent to state in one line, before each tool call, (a) the hypothesis the call tests, (b) the observation that would falsify it, and (c) one prior tool result that does not already answer the question; undefined falsifier means skip the call as corroboration-only. Subagent A reports findings as SARIF-lite blocks (tool, ruleId, level, location, fingerprint, rubric, evidence). Every finding must quote a specific `path:line`. **Read-only-git constraint (shared-tree safety):** Subagent A (and any subagent dispatched while the orchestrator is working) inspects version history READ-ONLY, `git show <sha>:<path>`, `git diff <a> <b>`, `git log`, `git show <sha> --stat`; it MUST NOT run `git checkout` / `switch` / `reset` / `stash` or anything that moves the working tree's branch or HEAD, because the orchestrator may be on a concurrent feature branch in the same working tree. (A prior subagent's `git checkout` to "judge at a revision" switched the orchestrator's branch and mis-branched a commit onto local `main`; grc_library #866. Judge the revision under review with `git show`/`git diff`, never a checkout.) A `run_all_audits.sh` regression-suite FAIL on transient `tests/tmp/*` fixtures, or a gate-50 flag for a not-yet-batched later PR's QA row, is a concurrent-run artefact, not a defect.

4. **Targeted cross-reference check**: for each touched file in the PR, identify which OTHER files in the corpus cite it (use `grep -rln "<basename>" --include="*.md"`). For each citing file, do a shallow check: does the citation still resolve (the cited section, version, line is still valid on the branch being finalized)? has the touched file's header text changed in a way that breaks the citer's quoted text? has any cross-reference become stale (e.g., the cited PR number is now wrong, the cited Version is now wrong)? This is a subset of `validation-sweep` Subagent B's scope, restricted to citers of the touched files only.

5. **Triage and record**: triage findings as in-window (PR introduced; fix in THIS PR before finalizing, a dedicated hot-fix PR only if the fix genuinely cannot land in-PR) or out-of-window (PR exposed pre-existing issue; surface to operator with named options). Record a per-PR validation file at `grc_library_private/.working/validate-pr/<YYYY-MM-DD>-PR-<N>.md` with six top-level H2 sections (Trigger and state snapshot, Subagent A return, Cross-reference check, Orchestrator triage, Resulting hot-fix PR if any, Notes). Append a row to `grc_library_private/.working/validate-pr/history.md` for every invocation regardless of findings (zero-finding rows still get a history entry; only the per-PR record file is conditional on findings). Before committing either surface, verify each fixed-in-window claim against the actual diff (grep for the claim's target text); a claim whose edit is absent is downgraded to routed, never recorded as fixed.

Termination: this is a single-iteration cycle (dispatch, check, triage, record). Findings are normally fixed in THIS PR before merge; a dedicated hot-fix PR is the exception, and it runs its own synchronous `/validate-pr` before it merges.

**Synchronous same-PR recording (the recursion-avoidance batching is retired).** Every PR runs its own `/validate-pr` before it is finalized, and every invocation's outputs land in the SAME PR, recording that PR's own number. The old cascade (each PR's row or fix needing a next PR, whose own `/validate-pr` compounds) is dissolved by recording in-PR: (1) zero-finding invocations write the history row into THIS PR's diff; (2) findings-producing invocations fix the finding IN THIS PR before merge (a dedicated hot-fix PR only when the fix genuinely cannot be co-committed), and the row records the finding fixed in the same PR. No placeholder and no back-fill: open PR, run the sweep, disposition findings, write the row, commit, let CI re-run, merge. Gate 50's Check 1 enforces this (window inclusive of `max_pr`; a row that records the QA as DISPATCHED / RESULT PENDING and never RETURNED fails).

**No orchestrator-side skip discretion.** The mandatory pre-merge finalizing invocation has no carve-outs for "meta PRs", "housekeeping PRs", "sweep close-outs", "the PR that introduces this skill", or any other class. The orchestrator does NOT have discretion to skip a `/validate-pr` invocation based on a judgement that the PR is "too small to need it", "circular", or "already validated by another mechanism". Every successful merge triggers a `/validate-pr`. If the run returns zero findings, the history-row records that zero-findings state, which is itself the proof-of-discipline. Skipping a quality-assurance step is a policy deviation the orchestrator cannot authorize unilaterally; only the project maintainer can grant a documented exception, recorded explicitly in the history-row Summary cell with the rationale.

Reject any subagent finding that lacks an explicit `path:line` quote. A finding without quoted evidence is a hypothesis, not a finding; re-dispatch the subagent with a re-emphasized evidence requirement before recording.

`grc_library_private/.working/validate-pr/` is exempt from corpus audit gates (frozen-state archive). Existing `path:line` references in subagent reports are kept verbatim even if the lines later shift; the record is a moment-in-time artefact.

**Surface findings prominently in chat, not buried in artefact files.** When findings exist, the chat reply must enumerate them inline (per-finding: ruleId, severity/level, `path:line` location, one-line evidence quote, one-line impact, one-line recommendation, in-window vs out-of-window classification). The maintainer must be able to read the finding set without opening the per-PR record file or scrolling through CHANGELOG-detailed. The per-PR record file remains the authoritative archive; the chat surface is for awareness and triage.

Report back: the audit baseline result, the Subagent A findings (grouped by severity, with `path:line` evidence per finding), the cross-reference check results, the triage decisions, the resulting hot-fix PR (if any), the new history row, and the path to the per-PR record file (if findings exist).
