Run the `validation-sweep` procedure defined at [`.claude/skills/corpus-management/procedures/validation-sweep.md`](../skills/corpus-management/procedures/validation-sweep.md). Slash-command entry point is `/validate`; the underlying procedure name remains `validation-sweep`. Execute the corpus-wide regression sweep per the eight-step process the procedure encodes:

1. **Establish mechanical baseline**: run `.claude/skills/corpus-management/tools/run_all_audits.sh` standalone and capture the result. If any gate fails, fix the underlying defect first, then return to this step.
2. **Enumerate recent changes**: identify the focus window (default: the past two calendar days) via `git log --since="2 days ago" --name-only --pretty=format:""`, plus the current working tree via `git status --short`.
3. **Identify failure-mode classes in scope**: review the catalogued classes the mechanical gates do not cover (stale prose references, mis-attributed citations, multi-surface incompleteness, inferred-as-verified state assertions, per-document version-bump omission, generated-artefact lag, stale docstrings, cross-document term drift).
3a. **Run the deterministic pre-flight scanner**: `python3 .claude/skills/corpus-management/tools/sweep-preflight-scanner.py`. It surfaces high-recall regex candidates for semantic triage; exit 0 always. Pass the output to each review pass as a known-candidate list. The scanner applies in-scanner heuristics plus the exemption file at [`.claude/skills/corpus-management/tools/sweep-preflight-exemptions.json`](../skills/corpus-management/tools/sweep-preflight-exemptions.json) for unique edge cases.
4. **Run the three semantic review passes**: recent-change deep review (A), corpus-wide stale-reference sweep (B), and audit-programme integrity check (C), each from a self-contained brief, reading target files in full. All three passes run on every full sweep; the only sanctioned reduction is one the maintainer authorizes in advance and records with the sweep record. Findings are reported as SARIF-lite blocks (ruleId / level / location / fingerprint / evidence); every finding must quote a specific `path:line`. **Pre-tool verification preamble (AI-assisted passes)**: an AI-assisted pass states in one line, before each tool call, (a) the hypothesis the call tests, (b) the observation that would falsify it, and (c) one prior result that does not already answer the question, and verifies the previous call's actual result before relying on it; an undefined falsifier means skip the call as corroboration-only, and a prior result that already answers the question is cited in the finding rather than re-called. A pass transcript that chains calls without these per-call statements is rejected and the pass is redone. If the focus window shows no recent activity (a "cold" sweep), Pass A becomes a narrower spot-check of the most recently-merged changes (`git log -5 --merges`), so the pass always has a concrete target set.
5. **Synthesize findings**: dedupe by `(file_path, normalized_section, claim_type)`; tag each synthesized finding `R` / `I` / `K` (read-verified / inferred / already-known); adjudicate severity onto `must-fix-now | should-fix-in-this-change | track-as-follow-up` (pick higher on disagreement, record both); record pass provenance; re-examine large divergence once with both claims side by side. Cross-check against the project's false-positive memory.
6. **Triage**: for findings within the focus window, propose a concrete fix. For findings outside the focus window, surface them to the maintainer with named action options (act now, defer tracked, dismiss); do NOT auto-defer. Dismissed findings enter the accept-list with a fingerprint, a rationale, and an expiry date; the accept-list cannot grow net of fixes on a green close.
7. **Apply fixes, re-baseline, repeat**: apply the fixes, **commit them**, then re-run `.claude/skills/corpus-management/tools/run_all_audits.sh` on the committed state (git-history-aware gates only see committed history). Repeat from step 4 if new findings surface. Termination: (a) empty-delta primary stop; (b) patience-plateau after 2 non-shrinking iterations, surface the residual; (c) hard ceiling of 6 iterations, a defect signal, not completion.
8. **Record the sweep**: record every sweep, including zero-finding ones, in the project's own working records (date, scope bounds, passes run, findings and dispositions, resulting change). Before recording a fixed-in-window claim, verify the edit against the actual diff; a claim whose edit is absent is recorded as routed, never as fixed.

Reject any review finding that lacks an explicit `path:line` quote. A finding without quoted evidence is a hypothesis, not a finding; redo the pass with a re-emphasized evidence requirement before synthesizing.

**Present findings prominently, not buried in archived records.** When findings exist, enumerate them inline (per finding: ruleId, severity, `path:line` location, one-line evidence quote, one-line impact, one-line recommendation, in-window vs out-of-window classification). The archived record remains the durable trace; the inline presentation is for maintainer awareness and triage.

Report at the end: the audit baseline result, the review findings (grouped by severity, with `path:line` evidence per finding), the fixes applied, the final clean-bill status, and where the sweep was recorded.
