Govern a programme

How do I stand up or improve a governance programme?

Nobody adopts a governance library front to back. Pick the situation that looks like yours; each one stages a few next actions, grounded in documents you can adapt.

Four starting situations

Starting from nothing

No documented programme yet: perhaps a first security hire, a first board question, or a first customer questionnaire. Enter smallest-first, not everything at once.

Name the seats first. The minimum viable governance structure guideline defines three tiers of structure; pick yours before adopting a single control document.

Adopt the minimum viable set. The quickstart template defines the smallest coherent document set a new programme stands up first.

Plan the build-out. The startup roadmap template stages a core baseline plus modules keyed to what you actually do.

Choose an adoption mode. The adopter guide covers forking the repository, adopting the corpus only, or adopting the governance pack only.

Running, but undocumented

Controls exist in practice: backups run, access gets reviewed, incidents get handled. Little is written down, so none of it is provable. The work is baselining, not building.

Scope what applies. Work through the applicability decision tree to bound what your organization actually needs.

Map practice to the reference set. Use the adopter portal to find the reference document for each practice you run informally; the comparison is your gap list.

Score where you stand. The maturity scorecard turns the baseline into a current-state picture you can put in front of leadership.

Close gaps in obligation order. The compliance alignment matrix shows which documents support which framework requirements.

Governing a group of entities

Subsidiaries, shared services, mixed jurisdictions, and the standing temptation to fork the programme per entity. The aim is one coherent model, tailored at entity level.

Choose a topology first. The multi-entity adopter guide sets out three adoption topologies for groups, with the trade-offs of each.

Map roles per entity. The minimum viable governance structure guideline supplies the seat names to map onto each entity's real structure.

Layer jurisdictions instead of forking. Shared core documents, with annex overlays carrying the jurisdiction-specific obligations per entity.

Answering to a specific obligation

An audit, a regulator, or a certification target with a date on it. Work backwards from the obligation, not forwards from whatever is easiest to adopt.

Follow the compliance path. The meet-an-obligation path walks from your framework or law, through the mappings, to the supporting documents and the evidence an audit will ask for.

Cite current editions. The canonical citations register records the current published version of every standard and regulation the library cites.

The documents that stand a programme up
