## 1. F1 (warning). A thirteenth route, in reference form

I enumerated every reference-form shape and ran the gate on each:

```text
result            shape
FAIL(flagged)     full reference   [text][label]        <- closed in #1158
pass(COUNTED)     IMAGE reference  ![alt][label]        <- LEAKS its alt text
FAIL(flagged)     IMAGE reference with tokens in the label
FAIL(flagged)     collapsed        [text][]
FAIL(flagged)     shortcut         [label]
FAIL(flagged)     footnote marker plus definition
```

Token-level, the decisive comparison:

```text
![parallel execution worker fan-out][img]   -> ['execution','fan','out','parallel','worker']  LEAKED
![parallel execution worker fan-out](x.png) -> []                                             stripped
```

**Why.** `IMAGE_RE` is `!\[[^\]]*\]\([^)]*\)`, which requires the PARENTHESIS form, so an image written
in reference form never matches it. `REF_LINK_LABEL_RE` (the strip I proposed in #1158) then removes
only the `][img]` half, leaving `![parallel execution worker fan-out] ` for the tokenizer. So the alt
text of a reference-form image counts as prose while the alt text of an inline-form image does not.

**The alt-text leak predates my #1158 fix** (before it, both the alt text and the label leaked); my fix
closed the label half and left this half. That does not make the claim any less false.

**Failure scenario.** A command represents a subsection only by an image written in reference form,
`![parallel execution worker fan-out][diagram]`, and the gate counts the subsection as represented
although no prose describes it. Latent today: no command file uses image references, and the four
routes in TODO 3.115 are equally latent. But the claim in the record says the reference-form class is
closed, and it is not.

**Fix:** widen `IMAGE_RE` to cover the reference form, `!\[[^\]]*\](?:\([^)]*\)|\[[^\]]*\])`, and apply
it BEFORE `REF_LINK_LABEL_RE` so the image is consumed whole. That preserves the documented asymmetry
in both forms.

**Recommended wording, since the lesson is the wording as much as the code:** stop claiming a class is
closed. "The twelfth fail-open route" is a fact; "and the last of the REFERENCE-FORM routes" is a
prediction, and this is the second time a completeness prediction in this series has been falsified
within one PR of being made. TODO 3.115 already says "Do NOT assume the class is exhausted when these
four close", which is the right register; the CHANGELOG headline should match it.

## 2. F2 (note). The specification clause is inaccurate again, for the third time

`governance/specification-audit-programme.md:170` states that "an image is stripped whole including its
alt text". True for the inline form, false for the reference form (section 1). The previous order noted
that this clause had been rewritten twice and that "a third error would be the pattern worth naming".
**This is the third error, so I am naming it:** each rewrite has described the strip set correctly as of
the code it was written against, and each has been falsified by the next route found. The clause is
tracking a moving target one step behind.

**Recommendation:** have the clause describe the PRINCIPLE rather than enumerate the mechanism, for
example "prose excludes anything whose text is a key, a target, or invisible to a reader; see the
`content_tokens` docstring for the current strip set". The enumeration then lives in one place, next to
the code, and cannot drift.
